# KPI отдела ассистентов

Веб-приложение: ассистенты заходят по своему ключу и видят только себя,
руководитель отдела — весь отдел, руководитель компании — сводку и приёмку.

Всё считается из фактов, а не из чьих-то оценок. По каждой цифре можно
раскрыть, из каких задач и событий она сложилась.

## Что видно

**Ассистенту:** свой кэф, четыре оценки с раскрытием «откуда цифра»,
деньги за период и список задач с таймингами.

**Руководителю отдела:** таблица по всем — кэф, четыре оценки, закрыто/в работе,
медиана ответа в чате, сумма к выплате. Клик по строке открывает карточку
человека. Отдельным блоком — собственный результат лида: результат отдела,
фильтр, разгрузка и доля с того, что заработала команда.

**По каждой задаче:** когда поставлена, через сколько взята в работу,
сколько делалась, была ли просрочка, сколько раз возвращалась,
дёргали ли руководителя, итоговая оценка и полная лента событий.

## Как считается оценка задачи

Три признака снимаются автоматически:

| Признак | Откуда берётся |
|---|---|
| Успел в срок | время закрытия против дедлайна в карточке |
| Без правок | задача ни разу не вернулась из «На проверке» |
| Без вовлечения руководителя | руководитель не писал в карточке до закрытия |

Три признака → 8, два → 6, один → 4, ноль → 2.
Десятка — только если все три и руководитель отметил инициативу как полезную.
Сорванная задача — 0.

Единственное, что делает руководитель: «принято» или «вернуть», плюс
«пригодилось / нет» по инициативам. Всё остальное считает приложение.

Руководитель отдела может списать вовлечение как «вопрос был по делу» —
это фиксируется в ленте событий с комментарием, чтобы решение было видно.

## Развёртывание

```bash
npm install -g wrangler
wrangler login

# база
wrangler d1 create kpi                     # id из вывода вписать в wrangler.toml
wrangler d1 execute kpi --file=schema.sql --remote

# секреты
wrangler secret put BOOTSTRAP_SECRET       # одноразовый, для первого входа
wrangler secret put HOOK_SECRET            # для вебхука YouGile
wrangler secret put TG_SECRET              # для вебхука Telegram

wrangler deploy
```

### Первый вход

```bash
curl -X POST https://<ваш-воркер>.workers.dev/api/bootstrap \
  -H 'content-type: application/json' \
  -d '{"secret":"<BOOTSTRAP_SECRET>","name":"Ваше имя"}'
```

В ответе придёт ключ доступа — он показывается один раз, в базе хранится
только его отпечаток. Дальше все остальные ключи выдаются во вкладке
«Люди и настройки».

## Подключение YouGile

1. Получите ключ API: раздел с ключами в YouGile, либо
   `POST /api-v2/auth/keys` (нужен ID компании, см. `POST /api-v2/auth/companies`).
2. Вставьте ключ во вкладке «Люди и настройки».
3. Впишите ID трёх колонок: «В работе», «На проверке», «Готово» —
   по ним считаются тайминги и возвраты.
4. Проставьте каждому сотруднику его ID в YouGile.
5. Нажмите «Синхронизировать» — задачи подтянутся.

Для мгновенных таймингов настройте вебхук YouGile на
`https://<воркер>.workers.dev/api/hook/yougile` с заголовком
`x-hook-secret: <HOOK_SECRET>`. Без вебхука всё работает, но тайминги
округляются до часа — по расписанию синхронизации.

> Проверено по документации: базовый адрес `https://ru.yougile.com/api-v2`,
> авторизация `Authorization: Bearer <ключ>`, задачи `/tasks` и `/tasks/{id}`,
> ключи `/auth/keys`, компании `/auth/companies`. Названия полей задачи
> и точный формат вебхука сверьте в интерактивной документации своего
> аккаунта — при расхождении правится только `upsertTaskFromYougile`.

## Подключение Telegram

Бот: **@Hotassist_bot**. Токен хранится в секретах Cloudflare (`TG_TOKEN`)
и локально в `.dev.vars` — этот файл в `.gitignore` и в репозиторий не попадает.

1. **Отключите приватность** — без этого бот не увидит обычные сообщения группы.
   У `@BotFather`: `/setprivacy` → выбрать бота → Disable.
   Затем **удалите бота из чата и добавьте заново**, иначе настройка не применится.
   Проверить: `https://api.telegram.org/bot<TOKEN>/getMe` — нужно
   `can_read_all_group_messages: true`. Альтернатива — сделать бота
   администратором чата.
2. Добавьте бота в общий чат.
3. Поставьте вебхук:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<воркер>.workers.dev/api/tg/<TG_SECRET>"
```

4. Узнайте ID чата: напишите в чат любое сообщение и посмотрите
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — поле `message.chat.id`.
   Впишите его в настройках приложения.
5. Проставьте каждому сотруднику его Telegram ID (там же, в `getUpdates`,
   поле `message.from.id`). Без этого бот не поймёт, кто написал.

### Как считается скорость

| Событие | Что происходит |
|---|---|
| Сообщение руководителя или лида | открывается таймер |
| Первое сообщение ассистента | таймер закрывается, засчитывается первому ответившему |
| Ответ через reply | привязка к конкретному вопросу |
| Обращение по имени (text_mention) | ждём именно этого человека |
| Слово «срочно» в тексте | норма ответа 5 минут вместо 15 |

Рабочее окно — будни 9:00–22:00 МСК. Всё вне его помечается `in_hours = 0`,
в оценку скорости не идёт, но показывается в сводке отдельной строкой.

### Штрафы за молчание

Доля быстрых ответов считается **от всех вопросов**, а не только от отвеченных, —
промолчать не выгоднее, чем ответить поздно. Сверх этого:

- вопрос без ответа дольше `miss_after_min` (60 мин) в рабочее время — **пропуск**;
- ночной вопрос без ответа дольше `miss_night_hours` (12 ч) — тоже пропуск:
  отвечать ночью никто не обязан, увидеть утром — обязан;
- каждый пропуск снимает `miss_penalty` (0.5) балла;
- при `miss_cap_count` (3) пропусках включается потолок: скорость не поднимется
  выше `miss_cap_score` (5), сколько бы быстрых ответов ни было.

Через `escalate_after_min` (30 мин) бот сам напоминает в чат, отвечая на
зависшее сообщение. Это снижает число пропусков сильнее, чем любой штраф.

Первого числа в 09:00 МСК бот присылает руководителю отдела в личку сводку
за прошлый месяц: медиана ответа, доля быстрых, пропуски, ответы вне окна.

### Постановка задачи из чата

Руководитель отдела или владелец пишет в рабочий чат (или боту в личку):

```
/task @xenyav 3 Заказать ракетку
```

Бот заводит задачу в YouGile так, как если бы её поставили руками:
колонка «Добавлена» (первая из `column_backlog`, либо `task_new_column`),
исполнитель — по нику из вкладки «Люди и настройки» (`tg_username` →
`yougile_id`), стикер «Приоритет» — по числу (1, 3, 7 или 30, как в
`priority_states`). Дальше задачу ведут обычные механизмы: вебхук
регистрирует её в KPI, бот-ассистент пишет бриф и ставит дедлайн.

- число можно не писать — тогда ставится 3 (настройка `task_default_priority`);
- вторая строка сообщения уходит в описание карточки;
- ответ приходит reply на команду: номер задачи, исполнитель, срок по
  приоритету и кнопка «Открыть в YouGile»;
- ник не найден — бот перечислит, кого знает; привязать ник можно командой
  `/assist @ник Имя` в личке;
- правка уже отправленной команды задачу не дублирует;
- команда не открывает таймер ответа — это постановка, а не вопрос.

### Ограничения

- бот не видит переписку до своего добавления — замер начинается с нуля;
- текст сообщений не сохраняется: в базе только id, время и автор ответа;
- команде стоит сказать о боте до включения, а не после.

## Локальный запуск

```bash
wrangler d1 execute kpi --file=schema.sql --local
wrangler dev
```

Данные лягут в `.wrangler/state`, сеть не нужна.

## Структура

```
schema.sql          таблицы и настройки по умолчанию
src/worker.js       API, расчёт метрик, интеграции
public/index.html   интерфейс, один файл без сборки
wrangler.toml       конфигурация Cloudflare
```

Все суммы, нормы и ставки лежат в таблице `settings` и правятся
из интерфейса — трогать код для этого не нужно.
