Свой сервер Project Zomboid с модами — где держать и как поднять

Сервер должен стоять в Москве, на процессоре с быстрым ядром и с 12 ГБ памяти. Ниже: какую ветку игры выбрать под моды, у кого брать, чтобы не переплачивать, и как поставить всё самому по шагам.

42.21текущая стабильная версия; мультиплеер B42 в основной ветке с 29 июля 2026
12 ГБпамяти на сервер для 10–20 игроков с нормальным списком модов

1

Итог: что брать

Для Project Zomboid важны три вещи: быстрое ядро процессора, достаточно памяти под моды и близость к игрокам. Самый выгодный вариант — обычный VPS в Москве на свежем Ryzen.

Рекомендую

VPS в Москве на Ryzen 9 9950X — ARK-HOSTER

2 200 ₽ / мес
2 ядра Ryzen 9 9950X до 5,7 ГГц · 12 ГБ DDR5 · 100 ГБ NVMe · Москва (Tech.ru, ММТС-9)
  • Почему он. У этого процессора одно из самых быстрых ядер на рынке, а сервер Zomboid упирается именно в одно ядро. 12 ГБ — норма для 10–20 игроков с модами.
  • Если моды тяжёлые (большие карты, десятки модов на технику и предметы) — тариф на 3 ядра и 16 ГБ DDR5 за 3 050 ₽.
  • Оплата: Visa, Mastercard, «Мир», СБП. Бесплатный тест на 24–72 часа — можно проверить пинг у всех игроков до оплаты.
  • Проверить на тесте: выделены ли ядра под вас или делятся с соседями — на сайте это не указано. Если под нагрузкой сервер лагает при свободной памяти, причина скорее всего в этом.
  • Минус: панели нет, ставить самому по SSH. Инструкция — в разделе «Установка».
Без консоли

Игровой хостинг с панелью

Мод добавляется кнопкой, сервер перезапускается из браузера.

  • MASSPAS, Москва: i9-9900K, 9 ГБ — от 1 590 ₽, на Ryzen 9 9950X — от 2 600 ₽. Build 42 поддерживается, память можно докупить.
  • ARK-HOSTER GROW: 16 ГБ сразу и ежедневные бэкапы — 2 420 ₽.
Не брать

Где переплатите или будет лагать

  • Тарифы на Xeon E5 — старые серверные процессоры с медленным ядром. Памяти много, а сервер всё равно будет тормозить.
  • Тарифы на 6–9 ГБ без докупки памяти — для 15 игроков с модами мало.
  • «Hi-CPU» у облачных провайдеров — тот же Ryzen 9950X с 16 ГБ в Москве у AppleTec стоит 4 290 ₽, на 1 240 ₽ дороже.
Осторожно

Дата-центры за границей

  • Германия и Нидерланды дают ~49 мс из Москвы против 9–13 мс внутри страны.
  • Сети иностранных хостеров в России периодически блокируют. В декабре 2024 «Ростелеком» перестал пропускать соединения к части серверов в сети Hetzner. В апреле 2025 Роскомнадзор пригрозил ограничить работу 12 зарубежных хостеров, среди них Hetzner, AWS и DigitalOcean.
  • Вариант за 0 ₽ — сервер на ПК одного из игроков: нужны белый IP, открытые порты UDP 16261–16262 и компьютер, включённый всё время игры.

Build 42 или Build 41: решают моды

Сервер и все игроки должны быть на одной ветке, и каждый мод из набора должен её поддерживать. Моды под B41 на сервере B42 не работают, и наоборот.

СтатусСтабильная. 42.20 вышла с мультиплеером 29 июля 2026, 42.21 — 28 сентября 2026. Патчи выходят часто.Старая ветка, обновлений нет. Ставится через бета-ветку legacy41.

Как решить. Откройте каждый мод из набора в Workshop и посмотрите теги справа (Build 41 / Build 42). Если хотя бы один обязательный мод есть только под B41 — весь сервер ставится на legacy41. Если все моды поддерживают B42 — берите B42.

Сколько железа на 10–15 человек

Память определяет число игроков и модов, частота ядра — будут ли лаги при скоплении зомби. Ядер много не нужно: хватает 2–4 быстрых.

СценарийПамять Java (‑Xmx)RAM сервера
До ~10 игроков, лёгкие моды6 ГБ10 ГБ
10–20 игроков, обычный набор модовваш случай8–9 ГБ12 ГБ
20+ игроков или тяжёлые моды и карты12–13 ГБ16 ГБ

По расчёту ConnectHosting для B42: примерно 3 ГБ RAM должны оставаться вне памяти Java — для системы и самой игры.

Процессор и диск

  • Процессор: главное — производительность одного ядра. Ryzen 9 7950X/9950X или Core i9 — хорошо, Xeon E5 — плохо.
  • Диск: NVMe. Мир постоянно пишется на диск, на медленном диске он долго грузится и сохраняется.
  • Объём: игра, моды и бэкапы мира. Тарифы ниже дают от 60 до 150 ГБ — хватит.

6

Установка на Linux VPS по шагам

Шаги по официальной вики, для Ubuntu 22.04 или 24.04. Подключение по SSH из Windows: ssh root@IP_сервера в «Терминале» или в PuTTY. Файлы удобно править через WinSCP.

  1. под root

    Поставить SteamCMD и tmux

    SteamCMD скачивает сервер из Steam, tmux держит консоль открытой после отключения SSH. При установке SteamCMD согласитесь с лицензией (I AGREE).

    bash
    sudo apt update && sudo apt install -y software-properties-common
sudo add-apt-repository multiverse -y
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install -y steamcmd tmux
  2. под root

    Открыть порты

    Нужны два UDP-порта: 16261 (вход и список серверов) и 16262 (данные после входа). SSH разрешаем первым, иначе фаервол отрежет вас от сервера.

    bash
    sudo ufw allow OpenSSH
sudo ufw allow 16261/udp
sudo ufw allow 16262/udp
sudo ufw enable
  3. под root

    Создать пользователя для сервера

    Запускать сервер от root нельзя. Создаём pzuser и папку /opt/pzserver, затем переключаемся на него.

    bash
    sudo adduser pzuser
sudo mkdir -p /opt/pzserver
sudo chown pzuser:pzuser /opt/pzserver
sudo -u pzuser -i
  4. под pzuser

    Скачать сервер

    Скрипт обновления пригодится и дальше: этой же командой сервер обновляется после патчей. Для B41 замените строку app_update на app_update 380870 -beta legacy41 validate.

    bash
    cat > $HOME/update_zomboid.txt <<'EOL'
@ShutdownOnFailedCommand 1
@NoPromptForPassword 1
force_install_dir /opt/pzserver/
login anonymous
app_update 380870 validate
quit
EOL
/usr/games/steamcmd +runscript $HOME/update_zomboid.txt
  5. под pzuser

    Выделить память

    На Linux память Java задаётся в ProjectZomboid64.json. Для VPS на 12 ГБ ставим -Xmx8g, для 16 ГБ — -Xmx12g. Первая команда показывает, где и какие значения стоят сейчас, вторая меняет их.

    bash
    grep -n -o -- '-Xm[sx][0-9]*[A-Za-z]' /opt/pzserver/ProjectZomboid64.json /opt/pzserver/start-server.sh
sed -i -e 's/-Xmx[0-9]*[A-Za-z]/-Xmx8g/' -e 's/-Xms[0-9]*[A-Za-z]/-Xms4g/' /opt/pzserver/ProjectZomboid64.json

    Если -Xmx нашёлся только в start-server.sh, во второй команде замените путь на этот файл.

  6. под pzuser

    Первый запуск

    Сервер дважды попросит пароль администратора и создаст мир с настройками по умолчанию. Дождитесь сообщения об успешном старте, введите quit, а после остановки — exit, чтобы закрыть tmux.

    bash
    cd /opt/pzserver
tmux new -s pz
bash start-server.sh

    Появятся файлы ~/Zomboid/Server/servertest.ini (настройки сервера и моды), servertest_SandboxVars.lua (правила мира) и мир в ~/Zomboid/Saves/Multiplayer/servertest.

  7. под pzuser

    Настроить servertest.ini

    Откройте nano ~/Zomboid/Server/servertest.ini и поменяйте эти строки (остальные оставьте). Моды — в следующем разделе.

    servertest.ini
    PublicName=Наш сервер
# false — сервера нет в общем списке, вход по IP
Public=false
# пароль на вход для своих
Password=придумайте_пароль
# админы в лимит не входят
MaxPlayers=16
# время стоит, пока никого нет
PauseEmpty=true
# сохранять загруженные куски карты каждые 15 минут
SaveWorldEveryMinutes=15
# встроенные бэкапы при старте и при смене версии игры
BackupsOnStart=true
BackupsOnVersionChange=true
BackupsCount=5

    Строки с # — пояснения, в файл их не вставляйте. Правила мира (зомби, лут, скорость времени) проще настроить в игре: Host → Manage Settings, затем скопировать servertest_SandboxVars.lua на сервер.

  8. под root (выйти из pzuser: exit)

    Автозапуск через systemd

    Конфигурация по образцу из вики: команды серверу идут через файл-канал, при остановке он сначала сохраняет мир (save), потом выключается (quit).

    bash
    cat >/etc/systemd/system/zomboid.service <<'EOL'
[Unit]
Description=Project Zomboid Server
After=network.target zomboid.socket
Requires=zomboid.socket

[Service]
Type=simple
User=pzuser
WorkingDirectory=/opt/pzserver/
ExecStart=/bin/sh -c "exec /opt/pzserver/start-server.sh </opt/pzserver/zomboid.control"
ExecStop=/bin/sh -c "[ -n \"$$MAINPID\" ] || exit 0; echo save > /opt/pzserver/zomboid.control; sleep 15; echo quit > /opt/pzserver/zomboid.control"
Sockets=zomboid.socket
KillSignal=SIGCONT
TimeoutStopSec=120
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
EOL

cat >/etc/systemd/system/zomboid.socket <<'EOL'
[Socket]
ListenFIFO=/opt/pzserver/zomboid.control
FileDescriptorName=control
SocketMode=0660
SocketUser=pzuser
EOL

systemctl daemon-reload
systemctl enable zomboid
systemctl start zomboid
    Отличие от вики. В исходной версии канал удаляется вместе с сервером. Если сервер выключится сам (мод автообновления или падение), команда остановки пишет save/quit в пустоту: на месте канала появляется обычный файл, и следующий запуск ломается. Здесь канал живёт постоянно, команда остановки срабатывает, только если процесс жив, а Restart=always поднимает сервер через 30 секунд после падения. Проверено на макете в Ubuntu под systemd: самовыключение, падение, рестарт и остановка.

    Лог: journalctl -u zomboid -f. Команда серверу: echo "save" > /opt/pzserver/zomboid.control. Перезапуск: systemctl restart zomboid, остановка: systemctl stop zomboid.

  9. игрокам

    Подключиться

    В игре: Join → Favorites → Add («Присоединиться» → «Избранное» → «Добавить»). Указать IP сервера, порт 16261, пароль сервера, любое имя и пароль аккаунта — аккаунт создастся при первом входе. Моды скачаются автоматически.

7

Подключить свой набор модов

В servertest.ini моды задаются тремя строками. WorkshopItems говорит Steam, что скачать, Mods — что включить в игре, Map — какие карты загрузить. Чтобы мод работал, нужны первые две строки.

  1. Соберите коллекцию

    В Steam Workshop создайте коллекцию и добавьте в неё все моды набора. Её же раздайте игрокам, чтобы подписались заранее.

  2. Вытащите ID

    Вставьте ссылку на коллекцию в PZ ID Grabber (его советует вики) или в Mod ID Grabber от WinterNode — получите готовые строки.

  3. Проверьте варианты

    В одном элементе Workshop может быть несколько Mod ID: основной и варианты. Включайте только нужные, иначе моды могут конфликтовать.

  4. Вставьте и перезапустите

    Остановите сервер, впишите строки, запустите снова. Сервер скачает моды при старте.

servertest.ini · Build 42
# числа из ссылок Workshop (?id=…), через ;
WorkshopItems=1111111111;2222222222;3333333333
# ID модов из описания, в B42 — с \ перед каждым
Mods=\ModLibrary;\ModA;\ModB;\MapMod
# папки карт-модов, ванильная карта — последней
Map=MapModFolder;Muldraugh, KY
Слеш в B42. Если в строке Mods= нет \ перед ID, мод на B42 не загрузится, а сервер не выдаст ошибку. Это самая частая причина, почему моды не работают. В B41 слеш не нужен.
Порядок. Библиотеки и моды, от которых зависят другие («Requires …» в описании), ставьте в Mods= раньше зависимых.
Память. Каждая карта-мод и крупный набор предметов добавляют нагрузку. Если в наборе 2+ большие карты, сразу берите 16 ГБ.
8

Обслуживание: обновления модов и бэкапы

Сервер проверяет и скачивает моды только при запуске, а у игроков Steam обновляет их сразу. После обновления любого мода игроков перестаёт пускать с ошибкой «Workshop item version is different», пока сервер не перезапустят.

/usr/local/bin/pz-nightly.sh · под root
cat >/usr/local/bin/pz-nightly.sh <<'EOL'
#!/bin/sh
# предупредить игроков за 5 минут, если сервер запущен
if systemctl is-active --quiet zomboid; then
  echo 'servermsg "Restart in 5 min"' > /opt/pzserver/zomboid.control
  sleep 300
fi
# сохранить мир и остановить
systemctl stop zomboid
# архив мира, хранить 7 дней
tar -czf /root/pz-$(date +%F).tar.gz -C /home/pzuser --exclude=Zomboid/Logs Zomboid
find /root -maxdepth 1 -name 'pz-*.tar.gz' -mtime +7 -delete
# обновить игру (моды обновятся при старте)
sudo -H -u pzuser /usr/games/steamcmd +runscript /home/pzuser/update_zomboid.txt
systemctl start zomboid
EOL
chmod +x /usr/local/bin/pz-nightly.sh
echo '0 5 * * * root /usr/local/bin/pz-nightly.sh' > /etc/cron.d/pz-nightly

Рестарт каждый день в 05:00 по часам сервера (узнать их — команда date). Не хотите, чтобы игра обновлялась сама, — уберите строку со steamcmd и обновляйте руками после того, как убедитесь, что патч не ломает моды.

Мод обновился днём

Перезапустите вручную: systemctl restart zomboid. Чтобы это происходило само, есть мод Udderly Up To Date: он выключает сервер при обновлении мода, а Restart=always из шага 8 запускает его обратно со свежими модами. Перед установкой проверьте на странице мода, что он поддерживает вашу ветку.

Бэкапы — не только на сервере

Архивы в /root пропадут вместе с VPS. Раз в неделю скачивайте свежий pz-*.tar.gz через WinSCP. Перед крупными патчами делайте копию обязательно: обновления B42 иногда ломали сохранения.

Полезные команды

В консоли или в игре со слешем: save, quit, reloadoptions — применить правки servertest.ini без рестарта, help — список всех команд.

9

Если что-то не работает

Сервер виден, но при входе бесконечная загрузка или тайм-аут
Закрыт порт 16262/UDP: вход проходит через 16261, а данные идут по 16262. Проверьте ufw status и фаервол в панели хостера, если он там есть.
«Workshop item version is different» / «File doesn't match the one on the server»
Мод обновился у игроков, а сервер работает на старой версии. Перезапустите сервер — при старте он скачает свежие версии.
Моды не загружаются, ошибок нет
На B42 — нет обратного слеша перед ID в Mods=. Ещё бывает, что в Mods= вписано название мода из Workshop, а не его ID. ID берите из описания мода или из папки mods/ внутри него.
Сервер не стартует, ошибки памяти
Значение -Xmx или -Xms больше, чем есть на VPS. Посмотрите free -h и выставьте -Xmx примерно на 3 ГБ меньше общего объёма.
Часть игроков кикает с ошибкой контрольной суммы
Вики предупреждает о баге: DoLuaChecksum=true на Linux-серверах иногда даёт ложные срабатывания. Если версии модов у всех совпадают, а кикает всё равно, поставьте DoLuaChecksum=false. Это ослабляет защиту от подмены файлов, так что делайте это только на закрытом сервере с паролем.
После перехода с B41 на B42: «Assertion Failed: Illegal termination of worker thread»
По вики: проверьте, что в steam_appid.txt в папке сервера одна строка 108600. Если не помогло, сделайте копию папки ~/Zomboid и удалите её — сервер создаст новую при запуске.
У игрока персонаж застрял в пустоте
Игрок заходит со старым профилем. Пусть сменит имя аккаунта в окне сервера (например, player → player_1), сохранит и зайдёт заново.
