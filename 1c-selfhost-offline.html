1С:Бухгалтерия на своём сервере: как поставить и жить без интернета

Коробочная «1С:Бухгалтерия 8» штатно работает в изолированной сети: учёт, документы, зарплата и регламентированные отчёты не требуют соединения. Интернет нужен только для покупки, активации лицензии (есть обходы через файл и телефон), обновлений (ставятся с флешки) и онлайн-сервисов вроде отправки отчётности.

Учебная версия: только пощупать

  • Бесплатная учебная платформа подходит, чтобы посмотреть интерфейс и потренировать установку.
  • Лицензия прямо запрещает вести на ней реальный учёт. Лимиты: 2 000 записей в основных таблицах, 1 000 строк в табличных частях, один сеанс, нет клиент-сервера и COM-соединений, печать только из Конфигуратора.

Самое важное для офлайна

Лицензии: как активировать без сети и что их ломает

Основная поставка и каждое клиентское место защищены либо программной лицензией (пин-код → файл .lic, привязанный к железу), либо аппаратным USB-ключом. Для изолированного сервера оба варианта рабочие, но ведут себя по-разному.

Три способа получить программную лицензию

1. Через интернет — автоматически из диалога «Получение лицензии». На изолированном сервере недоступно.

2. Через файл запроса (основной офлайн-способ). В диалоге выбираете «Через файл», программа сохраняет текстовый файл запроса. Его переносят на любой ПК с интернетом и загружают на portal.1c.ru → «Получение лицензии из файла» либо отправляют письмом на lic@1c.ru с темой «Получение лицензии». В ответ приходит файл лицензии, который переносят обратно и указывают в том же диалоге. Так активируют и клиентские, и серверные, и Базовые лицензии.

3. По телефону. Оператору Центра лицензирования диктуют 48 цифр кода запроса, в ответ получают 120 цифр (8 строк по 15) и вводят вручную. Работает только для однопользовательских клиентских лицензий; серверные, многопользовательские и КОРП-лицензии по телефону не выдают. Телефон Центра лицензирования: +7 (495) 688-99-12, часы 9:00–18:00 мск.

Файл лицензии хранится на Windows в %ProgramData%\1C\licenses, на Linux в /var/1C/licenses. Его резервная копия бесполезна на другом железе, но спасает при переустановке ОС без замены компонентов.

К чему привязан файл .lic

  • Сетевое имя компьютера, объём ОЗУ, модель материнской платы, тип и версия BIOS, список дисков, список сетевых адаптеров и их MAC, список процессоров.
  • На Windows дополнительно: наименование, серийный номер, версия и дата установки ОС. Переустановка Windows = новая активация.
  • Не учитываются USB-накопители, RAS/WAN и Bluetooth-адаптеры. Платформа реагирует на удаление и замену компонентов, добавление допустимо.

Пин-коды и повторные активации

  • ПРОФ и клиентские лицензии: в комплекте основной и резервные пин-коды (по данным партнёров — 3 на одно рабочее место). Кончились — бесплатный запрос на lic@1c.ru с регномером и причиной, ответ 2–3 рабочих дня.
  • Базовая: один пин-код, который можно использовать только 3 раза. Дополнительные пин-коды для Базовых не выдают; если железо не менялось, Центр лицензирования может дать ещё одну попытку.
  • Если параметры владельца при повторной активации отличаются от первоначальных, система откажет: храните данные, введённые при первой активации.

Виртуальные машины

  • Лицензия берёт параметры виртуальной машины. Миграция между нодами с разным железом меняет сразу несколько параметров и ломает лицензию.
  • При активации отключите динамическое выделение памяти и зафиксируйте объём ОЗУ, MAC-адрес и имя хоста.
  • Снапшот ВМ с лицензией валиден, пока ВМ остаётся на том же хосте с теми же виртуальными устройствами.

USB-ключ как страховка

  • Аппаратная лицензия (USB-ключ HASP) не привязана к материнке и ОС: переставили ключ — работает. Для сервера без интернета и с планами на апгрейд это проще программной.
  • Минусы: ключ дороже электронной поставки, его можно потерять, на Linux и в ВМ нужен проброс USB и драйвер ключа.
  • Серверная лицензия тоже бывает в виде USB-ключа.

Два режима работы

Файловая база или клиент-сервер

Файловый вариант, по словам самой «1С», «рассчитан на персональную работу одного пользователя или работу небольшого количества пользователей в локальной сети». Всё остальное — кластер серверов 1С плюс СУБД.

Пошагово

Установка на изолированный сервер

Всё скачивается на компьютере с интернетом, переносится на флешке. Для доступа к releases.1c.ru нужен логин портала: Базовой хватает регистрации продукта, для ПРОФ/КОРП дистрибутивы и обновления отдаются только при действующем 1С:КП.

Путь A

Файловая база на Windows (Базовая или ПРОФ до 5 человек)

1. Скачать два архива

На releases.1c.ru: «Технологическая платформа 8.3» (ветка 8.3.27, сборка «для Windows»), и «Бухгалтерия предприятия, редакция 3.0» — полный дистрибутив Accounting_3_0_XXX_setup1c.zip (для Базовой — AccountingBase_…). Сразу же скачайте текущие дистрибутивы обновлений, чтобы не ехать за ними снова.

2. Поставить платформу

Запустить setup.exe платформы, выбрать «1С:Предприятие» (толстый + тонкий клиент). Серверные компоненты для файлового варианта не нужны.

3. Установить шаблон конфигурации

Распаковать архив конфигурации, запустить setup.exe — шаблон ляжет в %APPDATA%\1C\1cv8\tmplts\1c\Accounting\<версия>.

4. Создать базу из шаблона

В окне запуска «Добавить → Создание новой информационной базы → из шаблона». Или из командной строки:

"C:\Program Files\1cv8\8.3.27.XXXX\bin\1cv8.exe" CREATEINFOBASE File="D:\Bases\Buh"; ^
  /UseTemplate "%APPDATA%\1C\1cv8\tmplts\1c\Accounting\3_0_203_18\1cv8.cf" /AddInList "Бухгалтерия"

5. Активировать лицензию файлом

При первом запуске откроется диалог лицензии. Регистрационный номер, пин-код, данные владельца → «Через файл». Файл запроса на флешку → portal.1c.ru или lic@1c.ru → файл лицензии обратно.

6. Выключить интернет-сервисы и настроить копии

Администрирование → Настройки программы → Интернет-поддержка и сервисы → «Доступ к интернет-сервисам» (есть с релиза 3.0.173). Затем «Резервное копирование» по расписанию в папку на другом диске.

Путь B

Сервер 1С + PostgreSQL на Debian/Ubuntu (ПРОФ, 5–20 человек)

1. Скачать

«Технологическая платформа 8.3 → Сервер для DEB-based Linux» (единый дистрибутив setup-full-8.3.27.XXXX-x86_64.run в tar.gz), «PostgreSQL с патчем 1С» (DEB-пакеты, с того же releases.1c.ru) либо Postgres Pro 1C, и дистрибутив конфигурации.

2. Подготовить ОС

# шрифты MS Core Fonts обязательны: без них кривые формы и интерфейс
sudo apt update && sudo apt install -y ttf-mscorefonts-installer fontconfig imagemagick unixodbc locales
sudo locale-gen ru_RU.UTF-8
# ttf-mscorefonts-installer тянет шрифты из интернета — на изолированном сервере положите .ttf в /usr/share/fonts вручную и выполните fc-cache -f

3. Поставить сервер 1С

tar -xzf server64_8_3_27_XXXX.tar.gz
sudo ./setup-full-8.3.27.XXXX-x86_64.run --mode unattended --enable-components server,ws,server_admin
sudo systemctl link /opt/1cv8/x86_64/8.3.27.XXXX/srv1cv8-8.3.27.XXXX@.service
sudo systemctl enable --now srv1cv8-8.3.27.XXXX@default

Компонент ws — модуль для Apache, server_admin — утилиты ras/rac для администрирования кластера без Windows-консоли.

4. Поставить PostgreSQL из сборки 1С

sudo dpkg -i postgresql-*.deb   # пакеты из архива сборки 1С, все сразу
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'сложный_пароль';"

В postgresql.conf по рекомендациям партнёров и Postgres Pro: shared_buffers = 25 % ОЗУ, effective_cache_size = 50–75 % ОЗУ, max_connections = 500–1000, temp_buffers = 256MB, work_mem = ОЗУ/32–64, параллелизм запросов выключить.

5. Создать базу и загрузить конфигурацию

С любого ПК в сети тонким/толстым клиентом: «Добавить → Создание новой базы → На сервере 1С:Предприятия» (Srvr=имя_сервера; Ref=buh, СУБД PostgreSQL, пользователь postgres). Шаблон конфигурации ставится на этот клиентский ПК, база создаётся из него.

6. Активировать серверную и клиентские лицензии

Серверная — из консоли кластера или при первом подключении клиента, только «Через интернет» или «Через файл» (по телефону нельзя). Клиентские лицензии лучше тоже класть на сервер: тогда их раздаёт кластер и на рабочих местах активировать ничего не нужно.

7. Опционально: веб-доступ

sudo apt install -y apache2
sudo /opt/1cv8/x86_64/8.3.27.XXXX/webinst -publish -apache24 -wsdir buh -dir /var/www/buh \
  -connstr "Srvr=localhost;Ref=buh;" -confpath /etc/apache2/apache2.conf
sudo systemctl restart apache2   # http://сервер/buh

Наружу такую публикацию выпускать только через HTTPS с валидным сертификатом и дополнительной аутентификацией веб-сервера или VPN.

Изолированная сеть

Что работает без интернета, а что нет

Все онлайн-функции в типовой конфигурации идут через «Интернет-поддержку пользователей» (логин портала 1С). Без неё программа просто не подключает сервисы, учёт от этого не страдает. С релиза 3.0.173 есть отдельный выключатель «Доступ к интернет-сервисам», сделанный именно для коробок без сети, чтобы программа не пыталась тянуть курсы валют и классификаторы.

Работает полностью офлайн

  • Весь учёт: документы, проводки, ОСВ, закрытие месяца, НДС, налог на прибыль, УСН.
  • Зарплата и кадры в объёме Бухгалтерии 3.0, печатные формы, отчёты по сотрудникам.
  • Регламентированная отчётность: формы заполняются и проверяются локально, выгружаются в XML («Отчёты → Регламентированные отчёты → Выгрузить»). Отправить файл можно с любого другого ПК через кабинет ФНС или оператора ЭДО.
  • Банк через файлы: выгрузка платёжек и загрузка выписок в формате 1CClientBankExchange (текстовый kl_to_1c.txt) — тот же обмен, что и до появления DirectBank.
  • Загрузка классификаторов и курсов валют вручную из файлов, которые принесли на флешке.
  • Обновление конфигурации и платформы из файлов (см. ниже).

Отваливается без сети

  • 1С-Отчётность: отправка в ФНС/СФР/Росстат, требования и ответы, МЧД. Нужен интернет на рабочем месте с сертификатом (на Linux — КриптоПро CSP ГОСТ 2012).
  • 1С:Контрагент, 1СПАРК Риски, 1С-ЭДО, DirectBank — автозаполнение по ИНН, проверка контрагентов, электронные документы, прямой обмен с банком.
  • Автоматические обновления, курсы валют, классификаторы, адресный справочник через интернет-поддержку.
  • Облачный архив, 1С:Кабинет сотрудника, 1С:Линк, онлайн-справка.
  • Автоматическая активация лицензии — только через файл или телефон.

Обновления с флешки

  • Ритм релизов Бухгалтерии 3.0 в 2026 году: май — 1, июнь — 2, июль — 4 (3.0.201.16, 3.0.201.24, 3.0.202.14, 3.0.203.18). Формы деклараций меняются каждый квартал, поэтому обновляться придётся минимум раз в квартал перед отчётностью.
  • Цепочка: обновление ставится не с любой версии. В каждом дистрибутиве есть UpdInfo.txt со строкой FromVersions= — по ней собирают последовательность релизов, которую надо скачать целиком.
  • Порядок: выгрузка .dt → Конфигуратор → «Конфигурация → Поддержка → Обновить конфигурацию → Выбор файла обновления» (.cfu) → «Обновить конфигурацию базы данных» → первый запуск в «Предприятии» завершает обработчики обновления.
  • Платформа обновляется тем же дистрибутивом, что и при установке; в описании релиза конфигурации указана минимальная версия платформы.

Схема «полуофлайн», которая реально используется

  • Сервер с базой стоит в изолированном сегменте, у него нет шлюза в интернет. Только локальная сеть.
  • Одно рабочее место бухгалтера имеет выход в интернет, на нём стоит сертификат ЭП. Оно подключается к базе по локальной сети, и с него же отправляется 1С-Отчётность: сам сервер в интернет не выходит.
  • Обновления и файлы лицензий админ носит через этот же ПК. Полностью воздушный зазор нужен редко и стоит дороже в рутине.

Опыт эксплуатации

Подводные камни

Собрано из документации «1С», статей партнёров и профильных блогов администраторов (interface31.ru, infostart.ru, online-ufa.ru). Каждый пункт — реальный повод для простоя.

1

Антивирус режет файловую базу вдвое

Замер на платформе 8.3.20: Microsoft Defender снижает производительность файлового режима примерно в два раза. Исключение только папки с базой почти не помогает; нужно исключить каталог bin платформы целиком (все процессы из него) и файлы *.1CD, *.dt, *.cf, *.cfu, кэш в AppData.

2

Файл базы по сети

Файловая база на SMB-шаре работает ровно до первого обрыва сети или спящего ноутбука с открытой базой: «Ошибка совместного доступа к файлу», повреждение таблиц. Лечение — chdbfl.exe, затем «Тестирование и исправление» в Конфигураторе. Гигабит, SSD на сервере и ни одной Wi-Fi-рабочей станции.

3

Лицензия слетает от апгрейда

Замена материнской платы, сетевой карты, переустановка Windows и даже переименование компьютера приводят к «Задана неправильная привязка лицензии». У Базовой — всего 3 активации на пин-код. Планируйте железо сервера на годы вперёд или берите USB-ключ.

4

Ванильный PostgreSQL не подойдёт

Платформа при создании базы подключает расширения mchar, fulleq, fasttrun из патча 1С. В дистрибутивном PostgreSQL их нет, база не создастся. Брать только сборку с releases.1c.ru или Postgres Pro 1C, и версии ровно из списка совместимости.

5

Сервер МИНИ — это 5 сеансов, не 5 человек

Лимит считается по сеансам «Предприятия»: открытое второе окно, фоновая обработка или зависший сеанс занимают место. Шестое подключение не пустят. Апгрейд до полного сервера возможен с зачётом стоимости.

6

Шрифты и локаль на Linux

Без MS Core Fonts формы печатаются криво, а интерфейс «плывёт». Лицензия Microsoft запрещает класть их в дистрибутивы, поэтому на изолированный сервер шрифты несут вручную. Для диаграмм и PDF нужны ImageMagick и FreeType, для XLS — libgsf. Локаль ru_RU.UTF-8 обязательна.

7

Linux ≠ Windows для интеграций

COM-объекты — технология Windows: обработки, которые дёргают Excel/Word через COM, на Linux-сервере не заработают. Штатные экспорт в XLSX/PDF и печать работают. 1С-Отчётность на Linux поддерживается, но требует КриптоПро CSP и локали ru_RU.CP1251.

8

Обновления ПРОФ без КП не скачать

Через 3 льготных месяца доступ к релизам на releases.1c.ru для ПРОФ закрывается. Без обновлений первая же новая форма декларации сдаётся вручную. Либо платите 1С:КП Базовый (24 168 ₽/год), либо честно берите Базовую версию, если хватает одного пользователя.

9

Цепочка релизов и пропущенные обновления

Отстали на полгода — придётся ставить 5–10 обновлений подряд, каждое с обработчиками по базе. На файловой базе 3–5 ГБ это часы. Делайте .dt перед каждым шагом: откат из «середины» цепочки иначе невозможен.

10

Лимит 4/6 ГБ на таблицу

«Превышен максимально допустимый размер внутреннего файла» — база созданная до 8.3.8 держит страницу 4 КБ и лимит 4 ГБ на таблицу даже после обновления платформы. Лечится выгрузкой/загрузкой .dt на новой платформе или утилитой cnvdbfl с размером страницы 8–16 КБ.

11

Веб-публикация в интернет

Опубликованный Apache без TLS и с пользователем «Администратор» без пароля — классика взломов 1С. Если доступ снаружи нужен, то HTTPS с валидным сертификатом, базовая аутентификация веб-сервера или VPN, сложные пароли всем пользователям базы.

12

Резервные копии не равны выгрузке .dt

Для восстановления лучше хранить копию 1Cv8.1CD (или pg_dump), а .dt — для переноса и проверки. .dt из повреждённой базы часто не загружается. Копию файловой базы снимают при закрытых сеансах, иначе она неконсистентна.

Перед запуском

Чек-лист на изолированный сервер

Что должно лежать на флешке и быть сделано до того, как сервер отключат от интернета.

  • Дистрибутивы платформы (сервер + клиент под нужные ОС), конфигурации, PostgreSQL от 1С, Apache-модуль; плюс цепочка обновлений на ближайший квартал.
  • Регистрационные номера и пин-коды всех лицензий (основная поставка, клиентские, серверная), записанные данные владельца для повторных активаций.
  • Железо сервера зафиксировано: имя хоста, MAC, объём ОЗУ, диски. Для ВМ — выключена динамическая память, ВМ закреплена за хостом.
  • Шрифты MS Core Fonts (.ttf), ImageMagick, FreeType, libgsf, unixODBC — для Linux-сервера вместе с их зависимостями из локального зеркала apt.
  • Исключения антивируса на каталог платформы и файлы базы; расписание резервного копирования на отдельный диск/NAS и проверка восстановления из копии.
  • В базе выключен «Доступ к интернет-сервисам», установлены пароли всем пользователям, у «Администратора» пароль не пустой.
  • Решено, как сдаётся отчётность: выгрузка XML + отправка с внешнего ПК, либо одно рабочее место с интернетом и сертификатом для 1С-Отчётности.
  • Для ПРОФ — договор 1С:КП оформлен или осознанно отложен с датой, когда закончится льготный период.
