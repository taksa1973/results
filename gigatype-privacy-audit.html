Аудит приватности · Type (GigaType) 2.0.0 для Windows · 21 сентября 2026

Уходят ли данные из GigaType? Да — и отложенно тоже.

Распознавание речи действительно работает локально: модель GigaAM лежит внутри установщика, голос и текст на сервер не отправляются. Но приложение с первого запуска шлёт телеметрию с постоянным идентификатором на два сервера, хранит неотправленные события на диске и досылает их, когда появится сеть. Переключателя в интерфейсе нет.

2 сервера телеметрии 2 очереди на диске с досылкой 2 фоновые загрузки без спроса 0 переключателей в интерфейсе Голос и текст локально

Коротко

Ответ на вопрос

Вопрос был: «вообще никуда, даже отложенно, данные не уходят?». Проверено по коду самого установщика Type.exe (938 МБ, SHA-256 1692d773…6bcd), а не по обещаниям на сайте.

Отправка
Есть

PostHog (EU) и собственный сервер разработчика stats.multitool.works. Первые события first_app_opened и app_opened уходят при старте, до появления окна.

Отложенно
Есть

Две очереди .jsonl на диске. Нет сети — события ждут и уходят при следующем удачном запуске: в PostHog до 7 дней, в multitool — бессрочно (до 1000 событий).

Голос и текст
Локально

Модель GigaAM v3 (ONNX, 885 МБ) внутри сборки, инференс через Electron IPC. В телеметрию идут только длительность аудио и число символов/слов — не содержимое.

Что именно привязывается к вам

Два постоянных UUID — anonymous_user_id (хранится зашифрованным в telemetry/anonymous-user-id.enc) и install_id (telemetry/state.json). Они не сбрасываются между сессиями, то есть вся история одной установки склеивается в один профиль. Плюс app_version, platform, полная строка os_version (os.version(), например «Windows 11 Pro»), arch, session_id. IP-адрес сервер видит по определению.

Отключение
Только вручную

В настройках нет ни одного пункта. Работает только переменная окружения GIGATYPE_TELEMETRY_ENABLED=0 — её можно положить в файл .env в папке приложения. Загрузку с Hugging Face так не отключить — только файрволом.

Механика

Как работает отложенная отправка

Именно это делает ответ «нет» невозможным: даже если сейчас сети нет, событие не теряется.

Запуск, до окна

TelemetryService.init() → capture()

Создаются или читаются install_id и anonymous_user_id. События first_app_opened (один раз за установку) и app_opened пишутся в queue.jsonl, копия — через маппер в traction-queue.jsonl.

Сразу и каждые 30 секунд

flush() → fetch(POST)

Читает очередь с диска, берёт батч (20 для PostHog, 200 для Traction), шлёт. Успех — срезает отправленное. Ошибка или таймаут 5 с — файл переписывается целиком и остаётся ждать.

Каждая диктовка

dictation_started → … → dictation_finished

Шесть событий на одну диктовку с общим session_id: длительность и размер аудио, был ли распознан голос, число символов и слов до и после, метод вставки, три вида задержек, результат.

Выход из приложения

shutdown() → flush() обеих очередей

Последняя попытка отправить всё накопленное перед закрытием (таймаут 5 с, параллельно для обоих серверов).

Что подтверждает, что содержимое не уходит

Отправка проходит через белый список из 60 полей (ALLOWED_PROPERTIES в telemetryService.js); всё остальное отбрасывается. Полей с текстом транскрипта или аудио в списке нет — только raw_transcript_chars, raw_transcript_words, final_output_chars, final_output_words, audio_duration_ms, audio_size_bytes. Единственное свободное текстовое поле — safe_message ошибки (до 180 символов): в нём маскируются URL, e-mail и пути к пользовательским папкам, но если текст ошибки процесса вставки включит фрагмент буфера обмена, фильтр его не распознает. Это теоретический канал, в коде вставки такого не найдено.

Что действительно локально

Распознавание — да. И ещё пара вещей, о которых стоит знать

локально

GigaAM v3 RNNT (ONNX)

Файлы v3_e2e_rnnt_encoder.onnx (885 МБ), decoder, joint, vocab лежат в resources/gigaam-model. Инференс через onnxruntime в отдельном процессе, обмен — Electron IPC. HTTP-мост поднимается только с GIGAAM_HTTP_BRIDGE=1 и только на loopback.

локально

VAD и аудио

Silero VAD (ggml-silero-v5.1.2.bin) в сборке. Хранение аудио выключено (audioRetentionDays = 0), история транскриптов — в локальной SQLite.

локально, но

windows-text-monitor.exe

После вставки читает содержимое активного поля ввода через Accessibility API каждые 500 мс — чтобы понять, правил ли пользователь текст. В сеть не ходит, но по сути это чтение чужого окна.

локально, но

Сканер процессов (ps-list)

Опрашивает список процессов, ищет cpthost.exe (Zoom), ms-teams_modulehost.exe, webexmeetingsapp.exe для «детекции встреч». Имена процессов в телеметрию не попадают.

без спроса

Автозагрузка

ensureAutoStartEnabledByDefault() при первом запуске прописывает приложение в автозапуск Windows (openAtLogin: true, openAsHidden: true). Значит, телеметрия и проверка обновлений идут при каждом входе в систему.

спящий код

Форк OpenWhispr

По package.json это open-whispr 2.0.0: внутри остались модули аккаунтов (openwhispr.com/auth), Google Calendar, Qdrant, диаризации. Конфигурация VITE_AUTH_URL пустая — ветки не активны, но при обновлении могут включиться.

Интерфейс

Почему переключателя нет, хотя строка «Аналитика использования» в переводах есть

В словаре переводов (locales/ru/translation.json) лежит текст: «Аналитика использования — помогите нам улучшить Type, делясь анонимными метриками…». Но в скомпилированном интерфейсе эта строка нигде не используется — компонент, который её показывал в OpenWhispr, вырезан.

В хранилище настроек рендерера значение захардкожено: telemetryEnabled: !1 (всегда false), а setTelemetryEnabled — заглушка, которая пишет false независимо от аргумента. При этом main-процесс это значение не читает вообще: TelemetryService._resolveEnabled() смотрит только на переменную окружения и наличие API-ключа, который вшит по умолчанию. Итог: даже если бы тумблер отрисовался, он бы ни на что не влиял.

_resolveEnabled() {

Слова и код

Заявления сайта против того, что в сборке

«Работает локально, без интернета и полностью приватно» — заголовок главной страницы
частично

Распознавание — локально, это правда. «Без интернета» — распознавание не требует, но само приложение при каждом запуске обращается минимум к трём хостам. «Полностью приватно» — с постоянным идентификатором установки это утверждение не выдерживает проверки.

«Голос и распознанный текст остаются на компьютере. Для распознавания они не отправляются на сервер» — политика конфиденциальности
подтверждается

Белый список полей телеметрии не содержит ни аудио, ни текста. Модель встроена, облачные провайдеры выключены и требуют своего ключа.

«Приложение собирает технические события: ошибки, длительность диктовки и количество символов» — политика конфиденциальности
неполно

Верно по существу, но не названы: получатели (PostHog в ЕС и сервер разработчика в Yandex Cloud), постоянные идентификаторы, версия ОС, хранение и досылка очереди, отсутствие способа отключить. Загрузка модели с Hugging Face и автообновление с SberCloud не упомянуты вовсе.

«MIT License… Тайп можно бесплатно использовать, копировать, менять…» — подвал сайта
не проверить

Лицензия MIT указана и в package.json, но исходники не опубликованы: mishanaer/GigaType2 отдаёт 404. Внешний аудит по коду возможен только через распаковку сборки, как сделано здесь.

Если всё-таки пользоваться

Как заглушить всё, что можно

Приложению сеть не нужна ни для чего полезного: модель внутри, обновления можно ставить руками. Три шага закрывают все найденные каналы.

1

Файл .env в папке приложения

main.js:130 читает .env из userData. По package.json имя приложения open-whispr, значит путь: %APPDATA%\open-whispr\.env (проверьте, какая папка появится после первого запуска).

GIGATYPE_TELEMETRY_ENABLED=0
GIGATYPE_DISABLE_AUTO_UPDATES=1

Создать до первого запуска, иначе first_app_opened успеет уйти. После — удалить папку telemetry с очередями и идентификаторами.

2

Исходящий запрет в файрволе

Переменной для Hugging Face нет, поэтому надёжнее запретить исходящие соединения самому процессу. От имени администратора:

New-NetFirewallRule -DisplayName "Type: no outbound" `
  -Direction Outbound -Action Block `
  -Program "$env:LOCALAPPDATA\Programs\Type\Type.exe"

Путь к Type.exe уточните после установки (NSIS ставит в %LOCALAPPDATA%\Programs\… для текущего пользователя).

3

Автозагрузка и проверка

Убрать Type из автозапуска (Диспетчер задач → Автозагрузка), иначе он будет пробовать сеть при каждом входе.

Проверить, что ничего не уходит: Get-NetTCPConnection -OwningProcess (Get-Process Type).Id после диктовки должен показывать только loopback. Очередь telemetry\queue.jsonl при рабочем запрете будет расти — это и есть «отложенные» события, которые ждут своего часа.

Альтернатива без компромиссов. Та же модель GigaAM v3 ONNX (istupakov/gigaam-v3-onnx на Hugging Face) открыта и работает через onnxruntime без всего этого обвеса. Если нужна именно офлайн-диктовка на русском, дешевле собрать тонкий скрипт вокруг модели, чем вырезать телеметрию из чужого Electron-приложения.
