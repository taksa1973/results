# amo-transcript-worker

Кладёт расшифровку звонка **текстом в примечание сделки**, чтобы менеджеру не
приходилось скачивать и открывать файл «Перевод звонка в текст.txt».

## Зачем

Телфин по окончании разговора прикрепляет к карточке **контакта** файл с полной
расшифровкой — это штатная функция интеграции
[Телфин.Офис ↔ amoCRM](https://www.telphin.ru/static/docs/support-pdf/amocrm_telphin_office.pdf)
(стр. 35–36, «Автозаполнение комментариев к звонкам»). Распознавание уже
оплачено по тарифам Яндекса (0,65 ₽ за минуту), поэтому воркер ничего не
распознаёт заново: он берёт готовый текст и переносит его в ленту сделки.

Второй тумблер той же интеграции — «Загружать краткий пересказ звонка» — даёт
короткое резюме примечанием (`extended_service_message`), но не полный текст и
не в сделку. Этот воркер закрывает вторую половину задачи и с пересказом
уживается: они друг другу не мешают.

## Поток

```
звонок завершён
   ↓  (1 секунда)
Телфин кладёт «Перевод звонка в текст.txt» на карточку контакта
   ↓  вебхук note_contact
воркер догружает примечание по id  →  тип attachment? имя файла подходит?
   ↓
Drive API: GET /api/v4/account?with=drive_url → GET {drive}/v1.0/files/{uuid}
           → _links.download.href → текст
   ↓
рядом ищется примечание-звонок (направление, длительность, номер — для шапки)
   ↓
POST /api/v4/leads/{id}/notes — текст примечанием в последнюю сделку контакта
   ↓
файл откручивается от карточки и удаляется из хранилища (DELETE_FILE)
   ↓
DeepSeek → «Итог звонка · … / Договорённости / Следующий шаг» — ещё одним
примечанием, на секунду позже расшифровки (SUMMARY)
```

## Токены: их два

amoCRM выдаёт права поштучно, и в одном токене может оказаться только `files`
или только `crm`. Воркеру нужны оба действия, поэтому в `.env` два поля:

| Поле | Право | Зачем |
|---|---|---|
| `AMO_TOKEN` | `crm` («Данные аккаунта») | читать примечания, писать текст в сделку |
| `AMO_FILES_TOKEN` | `files` («Доступ к файлам») | скачать расшифровку из хранилища |

Если у одного токена отмечены оба права — достаточно `AMO_TOKEN`, второе поле
оставить пустым.

Как выпустить: amoCRM → **Настройки → Интеграции → «+ Создать интеграцию» →
Внешняя интеграция**, отметить нужные права, **сохранить и установить**
интеграцию, затем вкладка **«Ключи и доступы» → «Долгосрочный токен»**.

Проверить, что у токена за права:

```powershell
node -e "console.log(JSON.parse(Buffer.from('<токен>'.split('.')[1],'base64')).scopes)"
```

**Если amoCRM отвечает `401 Неверный логин или пароль` на любой запрос** —
дело не в правах: токен не привязан к работающей интеграции. Проверить, что
интеграция сохранена, установлена в аккаунт и не выключена; после изменения
прав токен нужно выпустить заново.

## Деплой

```powershell
copy .env.example .env    # заполнить AMO_TOKEN и HOOK_SECRET
python deploy.py
```

Скрипт кладёт файлы в `/srv/amo/app/workers/amo-transcript/` на сервере
[neoved](../amo-server/), пересобирает образ (код внутри образа — bind-mount в
rootless Docker ломается по правам) и подписывает вебхук на `note_contact` и
`note_lead`.

## Проверка

```powershell
irm https://hooks.neoved.io/amo/amo-transcript/health
irm https://hooks.neoved.io/amo/amo-transcript/debug/<HOOK_SECRET>
```

Боевая проверка без ожидания звонка — прогнать уже существующий файл:

```powershell
irm "https://hooks.neoved.io/amo/amo-transcript/replay/<HOOK_SECRET>?note_id=<id примечания-вложения>&entity=contacts"
```

`note_id` берётся из API: примечания типа `attachment` с именем «Перевод звонка
в текст.txt». Повторный прогон того же файла ничего не сделает — стоит отметка
в KV (`done:<file_uuid>`, месяц).

## Разбор истории

Примечание создаётся с `created_at` = дата файла + 1 секунда, поэтому в ленте
оно стоит **сразу за файлом**, а не в конце — даже если звонок был месяц назад
и после него в карточке было много событий. Сделка тоже берётся «на тот
момент»: последняя из созданных не позже файла (+ `LEAD_GRACE_SEC`), а не
заведённая позже по другому поводу.

Сухой прогон — план без записи и удаления:

```powershell
irm "https://hooks.neoved.io/amo/amo-transcript/replay/<HOOK_SECRET>?note_id=<id>&entity=contacts&dry=1"
```

Ответ: `план: leads/38159855 · дата 2026-09-15T12:08:34Z · 1 прим., 7127 симв. · Расшифровка звонка · входящий · 6:18 · +7…`.

Повторная запись того же текста в ту же карточку не случится, даже если
отметка в KV потерялась: перед записью воркер сверяет начало текста с уже
имеющимися примечаниями (`alreadyThere`).

## Итог звонка

После расшифровки воркер просит DeepSeek составить итог и кладёт его
отдельным примечанием **на секунду позже** расшифровки — в ленте они стоят
парой: сначала текст, за ним итог. Формат фиксированный, без markdown
(примечания amoCRM — плоский текст):

```
Итог звонка · исходящий · 2:27 · +79055010109

<2–4 предложения: кто, что нужно, ключевые условия и цифры>

Договорённости
— …
— не зафиксированы   (если договорённостей нет)

Следующий шаг
<кто, что, когда>   /   не определён
```

Модель отвечает JSON (`summary`, `agreements[]`, `next_step`,
`next_step_date`) — поле с датой пока не используется, но лежит наготове под
задачу менеджеру. В промпте роли расшифровки объяснены явно: «Менеджер» — наш
сотрудник, «Клиент» — собеседник, который может оказаться банком или партнёром.

Итог к расшифровке, уже лежащей в сделке (разбор истории):

```powershell
irm "https://hooks.neoved.io/amo/amo-transcript/summarize/<HOOK_SECRET>?entity=leads&note_id=<id расшифровки>[&dry=1]"
```

Повторный вызов ничего не создаст: если следующей секундой за расшифровкой
уже стоит «Итог звонка», воркер выходит. Стоимость — около 0,05 ₽ за звонок
(deepseek-chat, ~1 500 токенов на вход и ~300 на выход).

## Настройки (.env)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `TRANSCRIPT_NAME_RE` | `перевод звонка в текст` | Какой файл считаем расшифровкой |
| `TARGET` | `lead` | `lead` — в сделку, `contact` — в контакт, `both` — в обе |
| `FALLBACK_TO_CONTACT` | `true` | Нет сделки — писать в контакт, чтобы текст не пропал |
| `MIN_DURATION_SEC` | `20` | Короткие разговоры пропускаем; 0 — писать все |
| `MAX_NOTE_CHARS` | `20000` | Лимит amoCRM, длиннее — режется на части |
| `CALL_WINDOW_SEC` | `900` | Окно поиска примечания-звонка для шапки |
| `HEADER` | `true` | Шапка «Расшифровка звонка · исходящий · 3:47 · +7…» |
| `DELETE_FILE` | `true` | Удалять файл после записи текста |
| `NOTE_AT` | `file` | Дата примечания: `file` — на секунду позже файла, `now` — момент обработки |
| `LEAD_GRACE_SEC` | `300` | Сделка выбирается среди созданных не позже файла + столько секунд |
| `SUMMARY` | `true` | Итог звонка через DeepSeek вслед за расшифровкой; нужен `DEEPSEEK_API_KEY` |
| `AI_MODEL` | `deepseek-chat` | Модель для итога |
| `AI_INPUT_CHARS` | `60000` | Сколько символов расшифровки отдаём модели |

## Что важно знать

- **Лимит примечания — 20 000 символов.** Проверено на живом аккаунте:
  20 001 → `400 TooLong`. Расшифровка занимает примерно 1 300 символов на минуту
  речи, то есть одно примечание вмещает ~15 минут разговора. Длинные режутся
  **по строкам** (реплика не рвётся посередине) на примечания с пометкой
  «часть N из M».
- **Тип примечания берётся из API, а не из хука.** В вебхуке `note_type`
  приходит числом, и код вложения нигде не документирован; по API он приходит
  строкой `attachment`.
- **Файл лежит на контакте, а примечание пишется в сделку.** Берётся последняя
  сделка контакта: звонок относится к текущему обращению, а не ко всей истории.
  Та же логика, что в [amo-phone-worker](../amo-phone-worker/).
- **Повторов не будет**: отметка `done:<file_uuid>` живёт в KV месяц, а amoCRM
  ретраит вебхуки.
- **Короткие звонки.** Телфин распознаёт даже 4-секундные разговоры, и в файле
  оказывается «Алло. Да. До свидания». Поэтому по умолчанию пишем только
  разговоры от 20 секунд.
- **Файл удаляется после записи.** Сначала `DELETE /api/v4/{entity}/{id}/files`
  (открепление от карточки), затем `DELETE {drive}/v1.0/files` (само
  хранилище). Удаление идёт строго после успешной записи примечания: если
  запись упала, до уборки дело не доходит. Если не удалось удалить — текст
  всё равно остаётся в сделке, а в журнале будет «файл остался (причина)».
- **Примечание-вложение в ленте остаётся.** Удаления примечаний в API v4 нет
  (`DELETE /api/v4/{entity}/notes` → 405), поэтому строка с именем файла в
  карточке контакта никуда не денется — не скачается только сам файл.
- **Удалённый файл лежит в корзине amoCRM** и восстанавливается методом
  `POST /v1.0/files/restore_`.
- **Расходы воркера — нулевые.** Ни распознавания, ни модели: только перенос
  уже готового текста.
