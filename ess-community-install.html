Element Server Suite Community на своём сервере: одна команда или по шагам

Два способа поднять полный Matrix-стек от Element (сервер Synapse, вход MAS, веб-клиент, админка, звонки Element Call, бот Hookshot) на одном Linux-сервере. Вариант 1 — скрипт, который делает всё сам. Вариант 2 — те же действия руками по официальному README репозитория element-hq/ess-helm, с объяснением каждого шага.

2 ядра · 2 ГБ RAM минимум 6 DNS-записей 4 порта Установка 10–20 минут
Что получится Перед установкой Вариант 1 · одна команда Вариант 2 · по шагам После установки Если 80/443 заняты Если что-то пошло не так Источники

Что получится

ESS Community — официальная бесплатная сборка Matrix от Element под лицензией AGPLv3, рассчитанная на команды примерно до 100 человек. Устанавливается в Kubernetes (k3s — облегчённая версия для одной машины) через Helm (установщик пакетов для Kubernetes).

Сервер и вход

  • Synapse — сам сервер Matrix, хранит комнаты и сообщения.
  • Matrix Authentication Service (MAS) — управляет пользователями и входом (пароли, в перспективе SSO).
  • PostgreSQL — база данных, ставится чартом автоматически (для долгой жизни README советует внешнюю).

Клиенты

  • Element Web — веб-клиент по адресу chat.ваш-домен.
  • Element Admin — консоль администратора по адресу admin.ваш-домен.
  • Element X на телефоне подключается к вашему серверу по имени домена.

Звонки и интеграции

  • Matrix RTC Backend — бэкенд Element Call (видеозвонки из Element Web и Element X).
  • Hookshot — бот для вебхуков GitHub, GitLab, Jira, RSS.
  • HAProxy и .well-known — маршрутизация и «визитка» сервера для федерации и клиентов.

Перед установкой

Три вещи, без которых не взлетит ни один из вариантов: подходящий сервер, шесть DNS-записей и открытые порты.

Сервер

  • ОС: чистый Ubuntu 22.04/24.04 или Debian 12 с systemd (стандарт для любого VPS). Подойдёт и другой Linux из списка k3s.
  • Ресурсы: минимум 2 ядра и 2 ГБ памяти по README; на практике для спокойной работы со звонками лучше 4 ГБ и SSD от 20 ГБ (образы занимают около 2 ГБ, дальше растут медиа и база).
  • Сеть: публичный IPv4-адрес; порты 80 и 443 свободны (нет nginx/apache/caddy). Если заняты — см. раздел про reverse proxy.
  • Доступ: root или пользователь с sudo.

DNS: шесть записей на IP сервера

Имя сервера нельзя поменять потом без сброса базы, выбирайте сразу. Все шесть — записи A (или CNAME) на один и тот же IP.

ИмяЗачем
example.comИмя сервера (server name): часть Matrix ID вида @user:example.com и адрес «визитки» .well-known
matrix.example.comSynapse — сюда ходят клиенты и другие серверы
account.example.comMatrix Authentication Service — страница входа
mrtc.example.comMatrix RTC — бэкенд звонков
chat.example.comElement Web
admin.example.comElement Admin

Порты

ПортДля чего
80/tcpHTTP, перенаправляет на HTTPS; нужен Let's Encrypt для проверки домена

Если на сервере включён ufw или firewalld, k3s рекомендует также открыть 6443/tcp и доверять внутренним сетям 10.42.0.0/16 (поды) и 10.43.0.0/16 (сервисы). Скрипт из варианта 1 делает это сам. Порты в панели хостера (облачный файрвол) открывайте руками.

Вариант 1 — одна команда

Скрипт install-ess.sh повторяет все шаги README в нужном порядке, проверяет сервер и DNS, ставит k3s, Helm и cert-manager, разворачивает чарт и создаёт первого пользователя. Повторный запуск безопасен: уже установленное пропускается, чарт обновляется до последней версии.

Честно о проверке. Скрипт прошёл shellcheck без замечаний и был запущен целиком в WSL Ubuntu 24.04 на этой машине в режиме без TLS: k3s, Helm, чарт 26.9.4 и первый пользователь поднялись, приложения отвечают — подробности в блоке «Что проверено». Ветка с Let's Encrypt на реальном домене не прогонялась — она повторяет команды README буква в букву, но первый запуск на боевом сервере делайте, глядя в вывод.

Запуск

На чистом сервере от root (или через sudo). Переменные задаются перед командой; без них скрипт спросит домен, e-mail и имя пользователя сам.

# 1) скачать и посмотреть, что внутри (скрипт открытый, 300 строк с комментариями)
curl -fsSL https://taksa1973.github.io/results/ess/install-ess.sh -o install-ess.sh
less install-ess.sh

# 2) запустить: домен, e-mail для Let's Encrypt, имя первого пользователя
sudo ESS_DOMAIN=example.com ESS_LE_EMAIL=admin@example.com ESS_ADMIN_USER=admin bash install-ess.sh

Если хочется совсем в одну строку (скрипт сам задаст вопросы в терминале):

curl -fsSL https://taksa1973.github.io/results/ess/install-ess.sh | sudo bash
Открыть install-ess.sh Код на GitHub

Что делает по порядку

  1. Проверяет root, systemd, curl; считает ядра и память; смотрит, свободны ли 80/443.
  2. Проверяет, что все шесть DNS-имён указывают на публичный IP сервера (иначе Let's Encrypt не выдаст сертификаты).
  3. Если включён ufw/firewalld — открывает 80, 443, 30001/tcp, 30002/udp, 6443 и внутренние сети k3s.
  4. Ставит k3s, ждёт готовности узла, кладёт kubeconfig в ~/.kube/config (и пользователю из sudo).
  5. Пишет настройку Traefik из README (доверять заголовкам подов, разрешать %2F и %23 в адресах).
  6. Ставит Helm, создаёт namespace ess и каталог ~/ess-config-values.
  7. Ставит cert-manager v1.17.0 и ClusterIssuer letsencrypt-prod, скачивает tls.yaml.
  8. Генерирует hostnames.yaml и выполняет helm upgrade --install с ожиданием до 30 минут.
  9. Создаёт пользователя через mas-cli manage register-user --yes --admin и печатает адреса, логин и пароль.

Ограничения

  • Только чистый сервер с systemd: в контейнере или на машине с уже занятыми 80/443 скрипт остановится (ESS_FORCE=1 — продолжить на свой страх).
  • Пароль первого пользователя передаётся в mas-cli аргументом — на долю секунды виден в списке процессов внутри пода. Для домашнего сервера некритично, для параноидального режима создавайте пользователя интерактивно (шаг 10 варианта 2).
  • Версии: k3s и Helm берутся последние стабильные, cert-manager закреплён на v1.17.0 как в README (меняется переменной CERT_MANAGER_VERSION).
  • Внешняя база PostgreSQL и SMTP для регистрации скриптом не настраиваются — это раздел advanced.md, см. «После установки».

Что проверено

Прогон 08.10.2026 в WSL2 Ubuntu 24.04 на этой машине (systemd, 12 ядер, 8 ГБ), режим ESS_TLS=none, домен ess.test через /etc/hosts.

  • Полный запуск завершился с кодом 0: k3s v1.36.5+k3s1 → Helm v3.22.0 → namespace → чарт matrix-stack 26.9.4 (helm upgrade --install --wait отработал примерно за 2,5 минуты после скачивания образов) → служба входа готова → пользователь @admin:ess.test создан через mas-cli.
  • 13 подов в Running/Completed: Synapse v1.162.0, Matrix Authentication Service 1.26.0, Element Web, Element Admin, HAProxy, PostgreSQL, Valkey, Matrix RTC (SFU и authorisation service), служебные job-ы.
  • Приложения отвечают (проверено через kubectl port-forward): Element Web 200, Element Admin 200, /.well-known/matrix/client отдаёт JSON с base_url и rtc_foci, Synapse /_matrix/client/versions 200, RTC authorisation /healthz 200.
  • Повторный запуск того же скрипта: 40 секунд, helm revision 2, на существующего пользователя — предупреждение, код выхода 0.
  • Две ошибки найдены и исправлены по ходу: kubeconfig писался раньше, чем k3s создавал /etc/rancher/k3s/k3s.yaml; и порядок команд из README (export KUBECONFIG до config view) на k3s 1.36 даёт пустой файл — скрипт и шаг 2 варианта 2 читают конфиг явно через --kubeconfig.
  • Не проверено: ветка Let's Encrypt (cert-manager + ClusterIssuer) на реальном домене — у WSL нет публичного IP; доступ снаружи через Traefik по 80/443 — в WSL сетевой стек k3s нестабилен (svclb и SFU перезапускались, Traefik отдавал 503), это ограничение WSL, а не чарта. На реальном VPS первыми проверьте именно их: kubectl get certificate -n ess и открытие chat.домен в браузере.

Вариант 2 — руками по шагам

Те же действия, что делает скрипт, но по одной команде с объяснением. Команды взяты из README ess-helm без изменений; выполняйте от root или через sudo.

1

Поставить k3s

Что это. k3s — Kubernetes «в одном файле», ставится одной командой и сразу запускает службу. Вместе с ним приходит Traefik (входной веб-сервер, который принимает 80/443 и раздаёт запросы сервисам).

curl -sfL https://get.k3s.io | sh -

Проверка: sudo k3s kubectl get nodes должен показать узел в состоянии Ready (обычно через 30–60 секунд).

2

Дать себе доступ к кластеру (kubeconfig)

Что это. kubeconfig — файл с адресом кластера и ключами. Без него kubectl и helm не знают, куда подключаться.

mkdir -p ~/.kube
sudo k3s kubectl --kubeconfig /etc/rancher/k3s/k3s.yaml config view --raw > ~/.kube/config
chmod 600 ~/.kube/config
chown "$USER:$USER" ~/.kube/config
export KUBECONFIG=~/.kube/config
echo 'export KUBECONFIG=~/.kube/config' >> ~/.bashrc

Отличие от README. В README сначала делается export KUBECONFIG на ещё не существующий ~/.kube/config, а потом k3s kubectl config view --raw. На k3s v1.36.5 (проверено 08.10.2026 в WSL) такой порядок даёт пустой файл: kubectl читает «конфиг» из указанного пустого пути и ничего не находит. Поэтому здесь источник указан явно через --kubeconfig, а export сделан после записи. Проверка: kubectl get nodes показывает узел Ready.

3

Настроить Traefik

Зачем. Два момента из README: Traefik должен доверять заголовкам X-Forwarded-* из внутренней сети подов (иначе Synapse не узнает реальные IP и схему), и разрешать закодированные символы %2F и %23 в адресах — их используют Matrix-клиенты. k3s подхватывает файл из этого каталога автоматически.

sudo tee /var/lib/rancher/k3s/server/manifests/traefik-config.yaml >/dev/null <<'EOF'
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: traefik
  namespace: kube-system
spec:
  valuesContent: |-
    ports:
      web:
        forwardedHeaders:
          trustedIPs:
            - "10.42.0.0/16"
            - "2001:db8:42::/56"
        http:
          encodedCharacters:
            allowEncodedHash: true
            allowEncodedSlash: true
      websecure:
        forwardedHeaders:
          trustedIPs:
            - "10.42.0.0/16"
            - "2001:db8:42::/56"
        http:
          encodedCharacters:
            allowEncodedHash: true
            allowEncodedSlash: true
EOF
4

Поставить Helm

Что это. Helm — менеджер пакетов для Kubernetes. ESS Community распространяется как Helm-чарт (пакет с шаблонами всех компонентов).

curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
5

Создать namespace и каталог настроек

Что это. Namespace — «папка» внутри кластера, куда попадут все компоненты ESS. Каталог ~/ess-config-values — ваши файлы настроек (values), которые передаются Helm при установке и каждом обновлении. Берегите его: без него обновить установку с теми же параметрами будет нечем.

kubectl create namespace ess
mkdir ~/ess-config-values
6

Поставить cert-manager (сертификаты Let's Encrypt)

Что это. cert-manager — компонент Kubernetes, который сам запрашивает и продлевает сертификаты. ClusterIssuer — запись «у кого запрашивать»: Let's Encrypt, проверка через HTTP на порту 80 силами Traefik. Версия v1.17.0 — та, что указана в README.

helm repo add jetstack https://charts.jetstack.io --force-update
helm install cert-manager jetstack/cert-manager \
  --namespace cert-manager --create-namespace \
  --version v1.17.0 --set crds.enabled=true

kubectl apply -f - <<EOF
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    privateKeySecretRef:
      name: letsencrypt-prod-private-key
    solvers:
      - http01:
          ingress:
            class: traefik
EOF

curl -L https://raw.githubusercontent.com/element-hq/ess-helm/main/charts/matrix-stack/ci/fragments/quick-setup-letsencrypt.yaml \
  -o ~/ess-config-values/tls.yaml

Файл tls.yaml содержит одну настройку: certManager.clusterIssuer: letsencrypt-prod. Если у вас уже есть wildcard-сертификат, вместо этого шага импортируйте его: kubectl create secret tls ess-certificate -n ess --cert=... --key=... и возьмите фрагмент quick-setup-wildcard-cert.yaml.

7

Записать имена хостов

Что это. hostnames.yaml — главный файл настроек: имя сервера и адреса пяти сервисов. Скачайте шаблон и замените your.tld на свой домен (или впишите файл руками, структура ниже).

curl -L https://raw.githubusercontent.com/element-hq/ess-helm/refs/heads/main/charts/matrix-stack/ci/fragments/quick-setup-hostnames.yaml \
  -o ~/ess-config-values/hostnames.yaml
sed -i 's/your\.tld/example.com/g' ~/ess-config-values/hostnames.yaml
cat ~/ess-config-values/hostnames.yaml
# что должно получиться
serverName: example.com
synapse:
  ingress:
    host: matrix.example.com
matrixAuthenticationService:
  ingress:
    host: account.example.com
matrixRTC:
  ingress:
    host: mrtc.example.com
elementWeb:
  ingress:
    host: chat.example.com
elementAdmin:
  ingress:
    host: admin.example.com
8

Установить ESS Community

Что происходит. Helm скачивает чарт из реестра GitHub (oci://), подставляет ваши values и создаёт все компоненты. Флаг --wait держит команду, пока всё не поднимется; образы качаются 5–15 минут в зависимости от канала.

helm upgrade --install --namespace "ess" ess \
  oci://ghcr.io/element-hq/ess-helm/matrix-stack \
  -f ~/ess-config-values/hostnames.yaml \
  -f ~/ess-config-values/tls.yaml \
  --wait

База PostgreSQL по умолчанию ставится чартом сама. Для внешней базы добавьте -f ~/ess-config-values/postgresql.yaml по фрагменту quick-setup-postgresql.yaml (хост, порт, пользователь, пароль и имя базы отдельно для Synapse и для MAS).

9

Проверить, что всё поднялось

kubectl get pods -n ess
kubectl get certificate -n ess        # READY должно стать True через 1–3 минуты

Все поды должны быть Running, сертификаты — Ready. Если сертификат висит в False, см. раздел про проблемы.

10

Создать первого пользователя

Почему руками. Регистрация по умолчанию выключена. Пользователей создаёт mas-cli внутри пода службы входа; команда интерактивная — спросит имя, предложит задать пароль.

kubectl exec -n ess -it deploy/ess-matrix-authentication-service -- mas-cli manage register-user

Неинтерактивный вариант (например, для скриптов): mas-cli manage register-user --yes --admin --password 'пароль' --email you@example.com alice. Флаг --admin даёт права администратора.

11

Войти и проверить

  • Откройте https://chat.example.com и войдите созданным пользователем.
  • Проверьте федерацию: federationtester.matrix.org, введите example.com.
  • На телефоне в Element X: «Войти», сервер example.com, логин и пароль.
  • Для наблюдения за кластером README советует k9s (консоль) или Lens.

После установки

Добавить людейЛибо mas-cli из шага 10 на каждого, либо включить саморегистрацию: для неё MAS нужен SMTP (почтовый сервер для писем подтверждения) — настраивается через дополнительные values по разделу «Configuring Matrix Authentication Service» в advanced.md.
ОбновлениеПовторите команду установки из шага 8 (или запустите скрипт ещё раз): Helm подтянет новую версию чарта с теми же values. Перед этим README просит посмотреть CHANGELOG на ломающие изменения.
helm upgrade --install --namespace ess ess \
  oci://ghcr.io/element-hq/ess-helm/matrix-stack \
  -f ~/ess-config-values/hostnames.yaml \
  -f ~/ess-config-values/tls.yaml --wait
БэкапПо maintenance.md: остановить Synapse и MAS, снять дамп PostgreSQL (pg_dumpall для встроенной базы), сохранить values, сгенерированные секреты и маркеры, скопировать том с медиа.
kubectl scale sts -l "app.kubernetes.io/component=matrix-server" -n ess --replicas=0
kubectl scale deploy -l "app.kubernetes.io/component=matrix-authentication" -n ess --replicas=0
kubectl get secrets -l "app.kubernetes.io/managed-by=matrix-tools-init-secrets" -n ess -o yaml > ess-secrets.yaml
kubectl get configmap -l "app.kubernetes.io/managed-by=matrix-tools-deployment-markers" -n ess -o yaml > ess-markers.yaml
Внешняя базаREADME прямо рекомендует для долгой жизни PostgreSQL из пакетов дистрибутива, а не встроенный. Переезд описан в advanced.md («Using a dedicated PostgreSQL database»); для новой установки проще сразу передать postgresql.yaml.
УдалитьДанные (тома PVC и сгенерированные секреты) при helm uninstall специально не удаляются, чтобы не потерять ключи подписи сервера.
helm uninstall ess -n ess
kubectl delete namespace ess
helm uninstall cert-manager -n cert-manager
/usr/local/bin/k3s-uninstall.sh
rm -rf ~/ess-config-values ~/.kube /usr/local/bin/helm

Если 80/443 уже заняты: за своим reverse proxy

Вариант из README для сервера, где уже живёт nginx или Caddy. Сертификаты выпускает ваш прокси, ESS отвечает по HTTP на внутреннем порту.

  1. Вместо файла Traefik из шага 3 положите вариант с портами 8080/8443 и внешним IP Traefik (его показывает kubectl get svc/traefik -n kube-system): 
    apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: traefik
  namespace: kube-system
spec:
  valuesContent: |-
    ports:
      web:
        exposedPort: 8080
      websecure:
        exposedPort: 8443
    service:
      spec:
        externalIPs:
        - <EXTERNAL-IP из вывода kubectl get svc/traefik>
  2. Вместо tls.yaml с Let's Encrypt возьмите фрагмент без TLS (в скрипте это ESS_TLS=none): 
    curl -L https://raw.githubusercontent.com/element-hq/ess-helm/refs/heads/main/charts/matrix-stack/ci/fragments/quick-setup-external-cert.yaml \
  -o ~/ess-config-values/tls.yaml      # содержимое: ingress.tlsEnabled: false
  3. Направьте все шесть имён с вашего прокси на внешний IP Traefik, порт 8080. Пример из README для Caddy (он сам выпустит сертификаты): 
    example.com matrix.example.com account.example.com mrtc.example.com chat.example.com admin.example.com {
  reverse_proxy http://127.0.0.1:8080
}
    Для nginx в README есть полный пример с заголовками Host, X-Forwarded-For, Upgrade и client_max_body_size 50M.

Если что-то пошло не так

Поды не поднимаются
kubectl get pods -n ess
kubectl describe pod <имя> -n ess
kubectl logs <имя> -n ess --tail=100
Pending с PVC — нет места или не работает local-path storage k3s; ImagePullBackOff — сервер не достаёт до ghcr.io; CrashLoopBackOff — смотрите логи.
Сертификат не выдаётся
kubectl get certificate -n ess
kubectl get challenge -n ess
kubectl describe challenge -n ess
В 9 случаях из 10 — DNS ещё не указывает на сервер или порт 80 закрыт снаружи. Let's Encrypt проверяет домен запросом на http://имя/.well-known/acme-challenge/.
Звонки: MISSING_MATRIX_RTC_FOCUSИз troubleshooting.md: проверьте, что https://example.com/.well-known/matrix/client отдаёт JSON с блоком rtc_foci, а https://mrtc.example.com/sfu/get открывается. Убедитесь, что 30001/tcp и 30002/udp открыты снаружи: nc -vnz IP 30001, nc -vnzu IP 30002.
Федерация не работаетПроверьте https://example.com/.well-known/matrix/server и federationtester. Имя сервера (example.com) обязано отдавать well-known — именно поэтому оно тоже должно указывать на этот сервер.
SFU в CrashLoopBackOffБэкенд звонков не достучался до STUN-сервера (определяет свой внешний IP). По troubleshooting.md — задать другие STUN-серверы или указать IP вручную в values. На сервере только с IPv4 помогает networking.ipFamily: ipv4.
Всё сломалось, начать зановоКоманды удаления из раздела «После установки», затем повторить установку. Сгенерированные секреты остаются в namespace: если хотите действительно чистый старт, удалите namespace целиком.
